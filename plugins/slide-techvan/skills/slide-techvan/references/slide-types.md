# スライドの型と deck.json の書き方

`PY "${CLAUDE_SKILL_DIR}/scripts/build_pptx.py" "資料.deck.json" -o "資料.pptx"` で PowerPoint を作る（PY は SKILL.md 3-1 で決めた Python のコマンド）。
deck.json は UTF-8 の JSON。文字の中の `**…**` は強調（太字＋強調色）になる。

## 全体

```json
{
  "title": "資料のタイトル",
  "author": "作成者・部署",
  "date": "2026年10月",
  "audience": "internal",         // internal（社内）/ client（顧客）
  "confidential": "internal",     // 省略可。本文ページ全体の既定の機密区分（internal / strict）
  "slides": [ { "type": "cover", ... }, ... ]
}
```

## 本文ページに共通の項目

表紙・章扉・最終ページ以外の型（本文ページ）は、次の項目を持てる。

| 項目 | 内容 | 必須 |
|---|---|---|
| `title` | 見出し。結論を言い切る文（36 文字以内） | ○ |
| `lead` | 見出しの下の補足 1 行（80 文字以内） | |
| `eyebrow` | 英字のラベル（例 `RESEARCH SUMMARY`） | |
| `eyebrow_ja` | 日本語のラベル（例 `調査サマリー`）。`label` と書いてもよい | |
| `callout` | 下に置く「まとめの一文」（60 文字以内） | |
| `confidential` | 機密のマーク。`"internal"`（社外秘・赤枠）/ `"strict"`（厳秘・赤地）/ `"none"`。基準は writing-rules.md「機密の扱い」 | |
| `note` | 下に置く注記・出典（120 文字以内） | |

ラベルを省略すると、直前の章扉（section）の `en` と `title` から自動で入る。
文字の中の半角スペースのうち、日本語と数字・英字の間のものは表示のときに取り除かれる（「3,240 件」→「3,240件」）。

## 構造

### cover（表紙）

```json
{"type": "cover", "title": "問い合わせ対応の品質分析", "subtitle": "過去1年のデータから見た改善の方向性",
 "badge": "報告書", "client": "サンプル株式会社 様", "date": "2026年10月", "author": "品質サービス事業本部"}
```
- `badge`: 小さなラベル（報告書・提案書・社内資料 など）
- `client`: 顧客向けのとき「○○株式会社 様」

### agenda（目次）

```json
{"type": "agenda", "title": "本日の内容", "items": [
  {"title": "現状の把握", "desc": "問い合わせの傾向"},
  {"title": "原因の分析", "desc": "対応が長引く5つの理由"}
], "current": 1}
```
- `items`: 2〜6 個。`desc` は任意。
- `current`: 章の途中で目次を再掲するとき、今の章（0 から数える）を強調する。
- ラベルは、指定がなければ「AGENDA - 目次 -」になる。

### section（章扉）

```json
{"type": "section", "number": "01", "title": "現状の把握", "subtitle": "問い合わせはどこで滞っているのか", "en": "Research"}
```
- `number` は「第1部」などの文字でもよい。`"variant": "dark"` で紺の章扉になる。
- `en` は英語の短い語。後に続く本文ページの英字ラベルになる。

### closing（最終ページ）

```json
{"type": "closing"}
```
- テンプレートの最終ページ（Thank you と会社情報）がそのまま使われる。書き足す項目はない。

### notes（注記・出典）

```json
{"type": "notes", "title": "注記および出典", "notes": ["本資料の数値は…", "…"], "sources": ["○○白書 2025年版", "…"]}
```
- `notes` と `sources` は合わせて 12 個まで（1 個 120 文字以内）。
- 2 つの枠は、短い文なら上下に、長い文なら左右に半分ずつ並ぶ。

## 要約

### summary（エグゼクティブサマリー）

```json
{"type": "summary", "title": "テスト工程の見直しで、出荷後の不具合は半減",
 "conclusion": "結論を2行以内で（例: 3つの施策で、出荷後の不具合を年間 40 件から 20 件に減らす）",
 "points": [
   {"heading": "原因は周辺条件に集中", "body": "公表事例の8割がタイミング・環境条件に起因"},
   {"heading": "開発者テストでは見つけにくい", "body": "…"},
   {"heading": "専門の観点で網羅できる", "body": "…"}
 ]}
```
- `points`: 2〜4 個（理由・根拠）。`{heading, body}` のほか、文字列だけ・見出しだけでもよい（そのときは番号付きの一覧で表示）。
- ラベルは、章扉より前に置いたときは「SUMMARY - 要約 -」になる。
- `conclusion` は 70 文字以内。

### next-actions（まとめ・次のアクション）

```json
{"type": "next-actions", "title": "11月中に2点を決定、12月から試行",
 "items": [
   {"action": "夜間当番の増員を決定", "owner": "情報システム部", "due": "11/15"},
   {"action": "よくある質問 20 件を公開", "owner": "ヘルプデスク", "due": "11/30", "note": "夜間に多い質問から"}
 ]}
```
- `items`: 1〜6 個。`note` は任意。`action` 30 文字・`note` 40 文字・`owner` 14 文字以内。

## 主張

### bullets（要点＋根拠）

```json
{"type": "bullets", "title": "…", "items": [
  {"text": "一次切り分けに平均 **42分** かかっている", "detail": "手順書が製品ごとに分かれており…"},
  "根拠のない短い要点だけでもよい"
]}
```
- `items`: 1〜6 個。`detail` は任意（90 文字以内）。

### kpi（数字の強調）

```json
{"type": "kpi", "title": "…", "items": [
  {"label": "年間の問い合わせ件数", "value": "12,480", "unit": "件", "note": "前年比 +18.2%"}
], "points": ["補足の箇条書き（任意）"]}
```
- `items`: 1〜4 個。`value` は数字だけ、`unit` は単位。

### quote（声・引用）

```json
{"type": "quote", "title": "利用者の声：手順がそろって迷わなくなった", "quotes": [
  {"text": "どの手順書を見ればよいか迷わなくなりました。", "who": "営業部 Aさん"},
  {"text": "夜間でも待たずに回答が来るようになった。", "who": "開発部 Bさん", "role": "リーダー"}
]}
```
- `quotes`: 1〜3 個。1 個なら 120 文字、2 個なら 90 文字、3 個なら 70 文字以内。

## 構成

### cards（並列の項目）

```json
{"type": "cards", "title": "…", "items": [
  {"label": "理由1", "heading": "手順書が製品ごとに分散", "body": "…", "points": ["…", "…"]}
]}
```
- `items`: 2〜6 個（5 個は上2・下3）。`label`・`points` は任意。
- 各カードには自動で番号（1, 2, 3…）が付く。`mark` で番号の代わりの文字（1〜2 文字）を指定できる。
- `label`: 見出しの前に付く（「理由1」のように数字で終わるラベルは番号と重なるので付かない）。
- `highlight`: 目立たせるカード（0 から数える。複数ならリスト）。5 枚のときは省略すると上の 2 枚が目立つ。

### compare（2列の比較）

```json
{"type": "compare", "title": "手順の一本化で、切り分けは3段階から1段階に",
 "left":  {"label": "現状", "heading": "製品ごとに手順書が分かれている", "points": ["…", "…"]},
 "right": {"label": "改善後", "heading": "症状から1つの手順に入る", "points": ["…", "…"]},
 "arrow": "一本化"}
```
- 左から右への変化（現状→あるべき姿、導入前→導入後）を示す。`arrow` は矢印に添える短い言葉（任意）。
- 右側が強調される。各側に `body`（60 文字以内）を書いてもよい。
- `heading` 30 文字以内、`points` は 5 個まで（`body` があれば 4 個）、1 個 30 文字以内。

### options（案の比較）

```json
{"type": "options", "title": "費用と効果のバランスはB案（段階導入）が最良",
 "options": ["A案：一括導入", "B案：段階導入", "C案：現状維持"],
 "criteria": ["効果", "費用", "期間", "リスク"],
 "scores": [["◎", "○", "△"], ["△", "○", "◎"], ["○", "○", "◎"], ["△", "◎", "○"]],
 "comments": ["全社で一度に効果", "2期に分けて導入", "費用はかからない"],
 "recommended": 1}
```
- `scores[i][j]` は 評価軸 i × 案 j。◎○△× または短い文字。
- `comments`: 案ごとの一言（任意、24 文字以内。案が 4 つなら 16 文字）。`recommended`: おすすめの案（0 から数える）。
- 案の名前は 案2つ 16 文字・3つ 12 文字・4つ 10 文字以内。評価軸は 6 個まで。

### matrix（2×2 のマトリクス）

```json
{"type": "matrix", "title": "着手は「効果が大きく、手間が小さい」2施策から",
 "x": {"label": "手間", "low": "小", "high": "大"},
 "y": {"label": "効果", "low": "小", "high": "大"},
 "quadrants": [
   {"title": "すぐやる", "items": ["よくある質問の追加", "回答テンプレート"]},
   {"title": "計画してやる", "items": ["受付システムの更新"]},
   {"title": "余力があれば", "items": ["…"]},
   {"title": "やらない", "items": ["…"]}
 ],
 "highlight": 0}
```
- `quadrants` の順番: 左上（効果大・手間小）→ 右上（効果大・手間大）→ 左下 → 右下。
- `highlight`: 強調する象限（0〜3）。
- 各象限の `items` は 4 個まで、1 個 24 文字以内（lead・callout・note をすべて使うときは 16 文字）。

### process（手順・フェーズ）

```json
{"type": "process", "title": "4ステップ・3か月で全社展開", "steps": [
  {"title": "現状調査", "period": "10月", "body": "問い合わせ記録の分析", "points": ["…"]},
  {"title": "手順の一本化", "period": "11月", "body": "…"}
]}
```
- `steps`: 2〜6 個。`period`・`points` は任意。
- `body` は ステップ3つまで 100 文字・4つ 70 文字・5つ以上 50 文字以内。`points` は 3 個まで（5 ステップ以上は 2 個）。

### tree（ロジックツリー）

```json
{"type": "tree", "title": "対応時間が長い原因は、人・手順・道具の3つ",
 "root": "対応時間が長い",
 "branches": [
   {"text": "切り分けが遅い", "children": ["手順書が分散", "履歴が探しにくい"]},
   {"text": "回答が往復する", "children": ["確認事項が不足"]},
   {"text": "待ち時間が長い", "children": ["夜間の人員不足", "引き継ぎ待ち"]}
 ],
 "highlight": 0}
```
- `branches`: 2〜4 個、`children` は各 0〜4 個。`highlight`: 強調する枝（任意）。
- `children` は 1 個 22 文字以内（枝に 3〜4 個あるときは 16 文字）。
- 根の箱は、強調した枝（なければ真ん中の枝）と同じ高さに置かれ、線がまっすぐつながる。

## データ

### table（表）

```json
{"type": "table", "title": "…", "header": ["#", "受付日", "内容"], "rows": [["A", "2026/02", "…"]],
 "col_widths": [0.5, 1.1, 3.2], "align": {"1": "c"}, "emphasis_col": 2}
```
- 10 行・7 列まで。`col_widths` は列幅の比率。`align` は列ごとの寄せ（l / c / r。省略時は数字の列は右、日付・記号の列は中央）。
- `emphasis_col`: 太字・見出し色にする列（0 から数える）。
- `highlight_row`: 見出しで触れている行（0 から数える。複数ならリスト）を色付き・太字で目立たせる。

### chart（グラフ）

```json
{"type": "chart", "title": "増えているのは夜間帯の問い合わせだけ",
 "chart": "column",               // column（縦棒）/ bar（横棒）/ line（折れ線）/ pie（円）/ stacked（積み上げ縦棒）
 "categories": ["4月", "5月", "6月"],
 "series": [{"name": "日中", "values": [420, 410, 430]}, {"name": "夜間", "values": [120, 150, 180]}],
 "unit": "件",
 "highlight": 1,                  // 強調する系列（任意）
 "points": ["夜間は3か月で 1.5 倍", "日中は横ばい"]}
```
- PowerPoint で後から編集できるグラフになる。`points` があると右側に読み取りのポイント（4 個まで）を置く。
- `points_title`: ポイント欄の見出し（既定は「読み取りのポイント」）。
- `highlight`: 系列が 1 つのときや円グラフでは、強調する項目（categories の位置）を指す。

## 計画

### schedule（スケジュール）

```json
{"type": "schedule", "title": "11月に試行、2月に全社へ展開",
 "periods": ["10月", "11月", "12月", "1月", "2月"],
 "tasks": [
   {"name": "現状調査", "start": 0, "end": 0, "owner": "情シス"},
   {"name": "手順の一本化", "start": 1, "end": 2},
   {"name": "全社展開", "start": 4, "end": 4, "milestone": true}
 ]}
```
- `start`・`end` は periods の位置（0 から数える）か、期間の名前（"11月" など）。`milestone: true` は節目（◆）。tasks は 8 個まで。
- `label`: 帯（節目は印の横）に添える短い文字（任意）。`owner` を省くと担当の欄は「—」になる。

### team（体制）

```json
{"type": "team", "title": "3チーム・9名の体制",
 "leader": {"role": "プロジェクト責任者", "name": "山田"},
 "groups": [
   {"role": "調査チーム", "name": "佐藤ほか2名", "note": "記録の分析"},
   {"role": "手順チーム", "name": "鈴木ほか3名", "note": "手順書の一本化"}
 ]}
```
- `leader`: 責任者（文字だけでもよい）。`groups`: 2〜5 個。`name` の代わりに `members`（名前のリスト）でもよい。

### cost（費用・見積）

```json
{"type": "cost", "title": "初期費用 480 万円、年間の運用費 120 万円",
 "items": [
   {"name": "調査・分析", "detail": "1か月", "amount": "120"},
   {"name": "手順書の整備", "detail": "2か月", "amount": "360"}
 ],
 "unit": "万円", "total": {"label": "初期費用 合計", "amount": "480"},
 "notes": ["金額は税抜き", "運用費は別途"]}
```
- `items`: 1〜8 個。`amount` は数字（カンマ可）。`total` を省くと、金額がすべて数字なら合計を自動で出す。
- `total` は数字だけでもよい。初期費用と運用費のように 2 つ出すときはリストにする（各 `{label, amount, note}`）。
  このとき `items` には **1 つ目の合計（初期費用など）の内訳** だけを書く。2 つ目（運用費など）は `total` にだけ書く。
  1 つ目の合計と内訳の和が合わないと警告が出る。

### risks（リスクと対策）

```json
{"type": "risks", "title": "主なリスクは2つ、いずれも事前の対策で抑制可能",
 "items": [
   {"risk": "現場の負担が一時的に増える", "level": "高", "measure": "移行期間は当番を1名追加", "owner": "情シス"}
 ]}
```
- `level`: 高・中・低。`owner` は任意。6 個まで。「高」の行は強調して表示される。

### status（課題・進捗一覧）

```json
{"type": "status", "title": "5件中4件は順調、1件は人員の手当てが必要",
 "items": [
   {"name": "よくある質問の追加", "status": "完了", "progress": 100, "owner": "ヘルプデスク", "due": "10/31", "note": ""},
   {"name": "夜間当番の増員", "status": "遅延", "progress": 30, "note": "候補者の調整中"}
 ]}
```
- `status`: 完了・進行中・遅延・未着手。`progress` は 0〜100 か "50%"（任意）。8 個まで。
  （同じ意味の言葉も使える: 済・達成 → 完了、対応中・順調 → 進行中、遅れ・要対応・注意 → 遅延、予定・保留 → 未着手）

### faq（よくある質問）

```json
{"type": "faq", "title": "よくある質問", "items": [
  {"q": "夜間でも電話で問い合わせできますか？", "a": "21時まで受け付けています。それ以降はチャットで…"}
]}
```
- `items`: 2〜5 個。`q` 40 文字・`a` 100 文字以内。4 個以上で収まらないときは 2 列になる。
