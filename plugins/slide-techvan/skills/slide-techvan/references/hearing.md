# 壁打ち（ヒアリング）の進め方

目的: 構成案を作るのに必要な情報だけを、少ない往復で集める。

## 基本の進め方

1. 依頼文と添付資料を読み、下の表の項目のうち**すでに分かっているもの**を埋める。
2. 分からない項目だけを質問する。1回の質問は最大4問まで（AskUserQuestion が使えるなら選択肢付きで）。
3. 「おまかせ」「急ぎ」と言われたら、既定値で進め、構成案のところでまとめて確認する。
4. 数字・事実はユーザーから受け取ったもの、または添付資料にあるものを使う。足りない中身は Claude が推測し、
   構成案に合意したあと「推測の確認」（SKILL.md）で選択式に確かめてから書く。

## 聞く項目と既定値

| 項目 | 質問の例 | 既定値（聞いても答えがないとき） |
|---|---|---|
| 資料の種類 | 提案書／報告・分析／社内報告／営業資料のどれに近いですか？ | 依頼文から推定 |
| 相手 | 誰が読みますか？（社内の誰か／お客様） | 社内（顧客なら書き方を「貴社・当社」、事実 → 分析 → 提言の順に） |
| 目的 | 読んだ人に何をしてほしいですか？（承認・理解・判断・購入） | 理解してもらう |
| 伝えたい結論 | 一番伝えたいことを一文で言うと？ | 依頼文から要約して確認 |
| 枚数 | 何枚くらいにしますか？ | 表紙・最終ページを除いて 5〜10 枚 |
| 素材 | 使える数字・表・事例はありますか？ | なし（足りない点は推測し、「推測の確認」で選択式に確かめる） |
| 期限・場面 | いつ、どんな場で使いますか？（会議・メール添付） | 会議で投影 |

## 推測の確認の質問の作り方

- 関係する点は 1 問にまとめる。基本は 1 回・4 問まで（2 回目は結論や数字に関わる点が残るときだけ）。数字・期限・結論に関わる仮説から聞く。
- 選択肢は 3 つ:「Claude の推測（理由を一言）（おすすめ）」「もう 1 つの案」「資料に入れない」。
  正しい値は「その他」で書いてもらう。
- 例（社内報告で、素材に日程が無いとき）:
  - 質問: 「推進役の選出と演習の開始は、いつにしますか？」
  - 選択肢: 「11月末に選出・12月に開始（部会の翌月から動ける日程）（おすすめ）」／「12月中に選出・1月に開始」／「資料に入れない」
- 例（分析で、原因の仮説を置くとき）:
  - 質問: 「待ち時間が長い主な原因として、どれを書きますか？」
  - 選択肢: 「判断を別部署に頼る流れ（照会の往復が多い記録から）（おすすめ）」／「担当者の人数不足」／「資料に入れない」
- 聞ききれない細かい点（作成者の部署名など）は、「次の点はこの案で書きます」と一覧で示してまとめて了承をもらう。

## よくある省略

- 「来週の部会で使う上期の報告資料を作って。数字はこのExcel」
  → 種類=社内報告、相手=社内、素材=あり。結論と枚数だけ聞く。
- 「○○社向けに、テスト自動化の提案書を」
  → 種類=提案書、相手=顧客。目的・結論・素材を聞く。

## 構成案の出し方（次の手順へ）

聞き終えたら、references/storylines.md の型をもとに次の形で示し、修正してもらう。

```
相手: 社内（部会）　　全 8 枚

 1. 表紙（cover）       社内ヘルプデスク 上期の振り返り
 2. 要点（bullets）     解決までの時間は 2割短縮。下期は夜間帯に注力します          機密: 社外秘
 3. 数字（kpi）         件数は横ばい、解決時間は 0.6 時間短縮                        機密: 社外秘
 ...
 7. 費用（cost）        増員の費用は年 480 万円、残業代の削減で 2 年で回収          機密: 厳秘
 8. 最終ページ（closing）
```

- 各行は「ページの型（type）」と「結論の見出し」と「機密」（厳秘／社外秘／なし。基準は writing-rules.md「機密の扱い」）。
- 合意が取れるまで deck.json は書かない。
