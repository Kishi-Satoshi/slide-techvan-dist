# 資料作成（slide-techvan）

テクバンのデザイン（紺と白のコーポレートデザイン、社内テンプレート ver1.1）で、
誰が作っても同じ見た目・同じ書き方の PowerPoint を作る。
流れは必ず「1. 壁打ち → 2. 構成案の合意 → 3. 生成 → 4. 確認 → 5. 改善メモ」の順に進める。
構成案に合意するまで .pptx を作らない。

このスキルのフォルダ: `${CLAUDE_SKILL_DIR}`

## 1. 壁打ち（内容を固める）

`${CLAUDE_SKILL_DIR}/references/hearing.md` に従う。
- 依頼文・添付資料で分かっている項目は聞かない。分からない項目だけ、1回 4 問まで聞く。
- 数字や事実は、ユーザーから受け取ったものか添付資料にあるものだけを使う。推測で数字を作らない。
- 相手が顧客か社内かで書き方のトーンを変える（顧客向け: 「貴社・当社」、事実 → 分析 → 提言。社内: 結論を先に、簡潔に）。
  deck.json の `"audience"` を `client` / `internal` にする。

## 2. 構成案を出して合意する

- 資料の種類ごとの標準の流れ: `${CLAUDE_SKILL_DIR}/references/storylines.md`
- 使える型（24種）と deck.json の書き方: `${CLAUDE_SKILL_DIR}/references/slide-types.md`
- 書き方のルール: `${CLAUDE_SKILL_DIR}/references/writing-rules.md`（見出しは結論を言い切る文、1スライド1メッセージ、文字数の目安）

- 24 種の型をすべて使った deck.json の見本: `${CLAUDE_SKILL_DIR}/examples/catalog.deck.json`
  （同じフォルダに、これで作った PowerPoint と一覧画像がある）

構成案は「ページ番号・型・結論の見出し・機密」の一覧で示し、修正を受けてから次へ進む。
機密の列は、writing-rules.md「機密の扱い」の基準で Claude が決める（厳秘／社外秘／なし）。
決めたとおり deck.json の `confidential` に書くと、ページの右上に CONFIDENTIAL のマークが付く。

## 3. 生成する

1. 使う Python のコマンドを決める。`python3 --version` → `python --version` → `py --version` の順に試し、
   最初に Python 3.8 以上と表示されたものを以下の `PY` に使う
   （Windows では `python3` が Microsoft Store の案内になっていることが多いので、`python` か `py` になる）。
2. python-pptx が使えるか確かめる: `PY -c "import pptx"`。
   失敗したら、そのまま `PY -m pip install python-pptx` で入れて続ける（了承は待たず、「部品を入れます」と一言伝える）。
   このスキルは Claude アプリのチャット・Cowork や Claude Code（クラウド）の実行環境で動く前提で、利用者の PC に準備は要らない。
3. 合意した構成を deck.json に書く（`<資料名>.deck.json` として UTF-8 で保存）。
   保存先は、利用者がダウンロード・確認できる場所にする。環境が出力用のフォルダを決めていればそこ
   （例: チャットの outputs フォルダ、Cowork の作業フォルダ）、無ければ作業フォルダ。.pptx も同じ場所に作る。
4. 生成する（パスに空白があってもよいように、パスは必ず "" で囲む）:
   ```
   PY "${CLAUDE_SKILL_DIR}/scripts/build_pptx.py" "<資料名>.deck.json" -o "<資料名>.pptx"
   ```
   - 終了コード 0 = 作成できた（「確認が必要な点」が出ていても作成はできている）。1 = 作成できなかった（表示された理由を直す）。
5. 「確認が必要な点」が出たら、文を短くする・項目を減らすなどして deck.json を直し、もう一度生成する。
   文字を小さくして詰め込む方向では直さない。

`${CLAUDE_SKILL_DIR}` はこのスキルのフォルダを指す（スキルを読み込んだときに実際のパスに置き換わる）。
置き換わっていない場合は、この SKILL.md があるフォルダのパスを使う。

## 4. 確認して渡す

- 画像にして見た目を確かめる（LibreOffice と、pdftoppm か PyMuPDF が必要）:
  ```
  PY "${CLAUDE_SKILL_DIR}/scripts/preview.py" "<資料名>.pptx"
  ```
  できた `<資料名>_preview/overview.png` を見て、はみ出し・重なり・空きすぎがないか確認し、あれば直す。
  （フォントが入っていない環境では文字幅が少し違うので、細かな改行位置は気にしすぎない）
- 画像にできない環境なら、「確認が必要な点」が 0 件であることを確かめ、PowerPoint で開いて確認してもらうよう伝える。
- 渡すときは、.pptx を利用者がダウンロードできる形で示し（環境にファイルを渡す仕組みがあれば使う）、
  PowerPoint でそのまま編集できること（文字・表・グラフは編集可能）を伝える。

## 5. 改善メモを送る（任意）

資料を渡したら、`${CLAUDE_SKILL_DIR}/references/feedback.md` に従って、作成中に起きたこと（直された構成・警告・見た目の修正）を
固有の情報を伏せてまとめ、**利用者に中身を見せて了承を得てから**管理者に送る。
このメモは週 1 回の自動改善でまとめて分析され、スキルの改善に使われる。送らないと言われたら、それ以上は聞かない。

## 守ること

- 見出しは結論を言い切る文にする（「売上推移」ではなく「売上は3期連続で増加」）。
- 1枚に詰め込まない。型ごとの上限（slide-types.md）を超えたら分ける。
- テンプレート（`assets/template.pptx`）のスライドマスター・レイアウトは消さない・変えない。
  生成した資料にもすべて残る（使わないものは表示されないだけ）。
- deck.json は作業フォルダに残し、修正の依頼があれば deck.json を直して作り直す。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 「python-pptx が入っていません」 | 3-2 のとおり `PY -m pip install python-pptx` で入れて続ける |
| 「保存できませんでした」 | 同じ名前の .pptx を PowerPoint で開いていれば閉じてもらう |
| 「テンプレートにレイアウト〜がありません」 | 管理者に連絡（`scripts/build_template.py` で template.pptx を作り直す） |
| 文字が収まらない警告が消えない | 項目を2枚に分ける、補足を note に移す |
| 色や型を変えたい・増やしたい | 管理者の作業（リポジトリの README.md「管理者向け」）。気づいた点は改善メモで送る |
